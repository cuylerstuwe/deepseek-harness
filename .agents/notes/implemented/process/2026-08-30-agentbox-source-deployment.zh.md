# Agent Note: Agentbox 源码部署

Status: implemented

[English](2026-08-30-agentbox-source-deployment.md) | 中文

## Problem

在持久化 Linux 智能体容器中从源码构建 Harness，需要可复现的构建、配置、启动和验证行为，同时不能把私有端点地址或凭据提交到分支。仅存在于一台开发机用户目录下的文件无法把这些行为交给另一个检出目录。

## Decision

`deploy/agentbox` 负责容器部署套件。安装器执行锁定依赖的生产构建，从环境变量渲染三个本地模型路由，把仅使用本地模型的 Cordis 策略链接到 Harness home，安装相对于仓库的启动包装器，并验证构建后的 CLI 与组合策略。可选的 `npx` 包装器会拦截直接调用 `@deepseek-ai/dsh` 的命令，并把其他包交给底层 npm 可执行文件。

私有地址和凭据保留在跟踪文件之外。提交的环境示例只包含占位符；每个操作者通过容器环境提供部署值，并且只把 `$DSH_HOME` 作为运行时状态持久化。

## Alternatives considered

**提交一份完整的 `settings.yaml`。** 这样设置更短，但会公开私有拓扑，并促使凭据或特定主机的回环地址进入源码管理。

**把开发者的 home 目录复制进容器。** 该副本会把配置与浏览器凭据、会话历史、生成的 profile、缓存和特定主机的符号链接混在一起。

**安装注册表包并在下载后打补丁。** 社区命令可能静默执行上游代码而不是该分支，重新安装也可能丢弃部署策略。

## Consequences

一个经过审查的检出目录包含容器所需的全部非秘密决策，同一个验证命令可以发现缺失构建、不完整的模型目录或被重新启用的 DeepSeek 服务。链接的包装器和策略要求检出路径持续可用，端点值必须能从容器网络访问，操作者必须有意传输 q27 凭据并持久化 Harness 状态。
